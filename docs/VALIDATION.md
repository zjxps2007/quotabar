## QuotaBar 이름 변경 및 저장소 준비 (2026-10-17)

- Swift 패키지·실행 파일·앱 파일·Dashboard helper·리소스 번들과 화면 이름을 QuotaBar로 변경했습니다. 산출물은 `artifacts/QuotaBar.app`, `artifacts/QuotaBar-macos-arm64.zip`입니다.
- 기존 데이터 경로와 앱 식별자는 유지했습니다. 이전 앱 종료 후 새 앱에서 실제 Codex 2계정과 최신 quota를 확인했으며 전체 설정 파일의 정규화된 SHA-256이 변경 전후 동일했습니다.
- 실제 Dashboard와 상단바 팝업의 QuotaBar 로고·제목을 화면으로 확인했습니다. 설정 화면의 버전 0.2.2, 새 GitHub 링크, macOS 앱 메뉴 이름도 확인했습니다. 검증 후 창을 닫아 Dashboard helper가 종료되고 QuotaBar 상주 프로세스 하나만 남았습니다.
- 릴리스 빌드, 주 앱과 helper의 strict 서명 검사, 두 번들의 리소스 원본 일치, 패키징된 Claude callback, ZIP 무결성 검사가 통과했습니다.
- 전체 **77개 테스트 / 9개 suite**가 통과했습니다. 첫 실행에서 로그인 timeout 테스트의 0.3초 제한이 모의 CLI 시작보다 먼저 끝나 기록 파일을 읽지 못했습니다. 해당 테스트만 3초의 시작 여유를 두도록 보완하고 전체 검사를 다시 통과했습니다. 실제 로그인 제한 300초는 변경하지 않았습니다.
- 공개 대상은 소스·리소스·테스트·문서 58개 파일입니다. 빌드·측정 파일, 개인 설정·로그인 파일은 제외했습니다. 이메일·키·토큰 패턴을 검사했고 발견된 문자열은 합성 테스트/미리보기 데이터 또는 파일 이름이었습니다. 원본 Apache-2.0 LICENSE와 NOTICE를 유지했습니다.

### 상단바 잔여율 표시 후속 변경

상단바 제목을 경고 계정 수에서 `Codex 38% · Claude 16% · Gemini 84%` 형식의 Provider별 잔여율로 변경했습니다. 활성 계정과 사용 기간 중 가장 낮은 값을 사용하고, 조회되지 않은 값은 `—`, 일부 계정의 최신 값 확인이 필요하면 `*`로 구분합니다. 메뉴의 계정 목록에는 모든 quota 기간을 표시하고 목록 높이가 0으로 접히지 않도록 보완했습니다.

릴리스 빌드와 로컬 서명 검사를 다시 통과했으며, 앱을 재시작하여 실제 Codex 잔여율이 47%로 표시되는 Dashboard 접근성 상태를 확인했습니다. 상단 상태 항목 자체의 텍스트와 수정된 팝오버의 시각 검증은 화면 제어 도구가 앱 창만 제공하여 완료하지 못했습니다. 기존 27개 회귀 검사는 앞선 구현의 검증 결과이며, 이번 표시 변경에는 별도 테스트를 추가하지 않았습니다.

### 상단바 팝오버 높이 조정 (2026-10-17)

계정당 220pt를 예약하던 목록 높이를 실제 콘텐츠 측정값으로 변경했습니다. 계정·quota 기간·오류 안내가 늘거나 줄면 목록 높이도 따라 바뀌며, 430pt를 넘으면 스크롤됩니다. 활성 계정이 없을 때는 빈 스크롤 영역을 만들지 않습니다.

릴리스 빌드와 로컬 서명 검사 후 실행 중인 앱에 반영했습니다. `Control-F8`로 실제 메뉴바 팝오버를 열고, Codex 1계정의 잔여율과 리셋 시각 아래에 버튼이 배치되어 이전의 불필요한 하단 공백이 사라진 화면을 확인했습니다. 이번 레이아웃 변경에는 별도 단위 테스트를 추가하지 않았으며, 아래 47개 검사는 이전 로그인 기능 검증 결과입니다.

## Codex 로그인·자동 갱신 추가 검증 (0.2.0)

- 기존 파일 연결 계정에서 **앱에서 로그인** → 공식 브라우저 로그인 실행 확인.
- 다른 계정으로 로그인했을 때 기존 카드를 변경하지 않고 계정 불일치 안내를 표시하는 것 확인.
- 사용자 선택에 따라 로그인한 계정을 새 카드로 추가. 기존 카드가 유지되고 총 Codex 2계정이 표시됨. 새 카드의 **자동 갱신**, 실제 주간 잔여율 74%, 리셋 시각 표시 확인. 개인정보와 인증 정보는 검증 파일에 기록하지 않음.
- 공식 CLI를 사용하는 실계정 로그인·키체인 저장·quota 조회는 검증됨. 실계정 토큰의 만료 시점까지 기다리거나 강제로 회전시키는 검사는 수행하지 않음. 자동 갱신은 모의 OAuth 응답으로 아래 경계 조건을 검사함.
- 20개 추가 테스트: 기존 설정 호환, 만료 판단, 요청 주소와 grant, 교체 refresh token 보존, 일부 필드 생략, 계정 변경 거부, 응답 내 비밀값을 오류에 포함하지 않기, 손상된 성공 응답, 동시 갱신 병합, 늦은 401 처리, 유효 기간 내 인증 거부, 삭제·재연결 경합, 키체인 저장 실패 후 복구, 만료 세션 반복 요청 중단, 로그인 URL 검증, 격리된 임시 홈 권한·정리, 취소·시간 초과·실패 처리, CLI 미설치 안내.
- 모든 47개 테스트와 릴리스 빌드·로컬 서명 검사 통과. 패키징된 Claude status line 검사도 재실행하여 통과.
- 완료 후 남은 `aiusage-lite-login-*` 임시 폴더 0개 확인. 두 번째 정상 앱 실행은 즉시 종료되어 중복 실행이 차단됨. 앱 재실행 후 두 계정과 새 계정의 자동 갱신 설정 복원 확인.

## 키체인 승인창 제거 검증 (0.2.1)

- 조회·로그인·토큰 갱신·삭제에서 사용하던 키체인 저장소를 `Credentials/`의 계정별 파일로 변경. 별도 암호화는 하지 않으며 폴더 0700·파일 0600 권한으로 보호함을 UI와 사용법에 명시.
- 이전 키체인 항목은 최초 한 번, 승인창이 금지된 상태에서만 읽기를 시도. 계정 정체성이 일치하고 파일·설정 저장에 성공한 항목만 이전 항목 삭제를 시도함.
- 실제 앱 실행에서 두 기존 계정의 무승인 키체인 접근이 거부되어 인증은 이전되지 않음. 계정 카드 두 개는 유지되고 **앱에서 로그인** 안내가 표시됨. 설정의 이전 완료 버전 1, 새 로그인 파일 0개를 내용 노출 없이 확인. 이 두 계정은 각각 한 번 재로그인해야 함.
- 0.2.1 실행과 수동 새로고침에서 키체인 승인창이 나타나지 않는 것을 접근성 상태로 확인. 새 저장소로의 실계정 재로그인 및 quota 조회는 아직 검증하지 않음.
- 추가 9개 검사: 사용자 전용 파일 권한, 재생성한 저장소에서 읽기, 회전·계정별 삭제, 크기 상한, 심볼릭 링크·하드 링크 거부, 실패 시 기존 값과 임시 파일 정리, 최초 한 번의 이전, 계정 불일치·접근 거부, 설정 저장 실패 시 이전 항목 보존 및 재시도, 앱 로그인 계정의 CLI 대체 금지, 갱신 토큰의 파일 저장·다시 읽기와 중복 갱신 방지. 모든 56개 테스트 통과.
- 릴리스 빌드·로컬 서명 검사·패키징된 Claude status line 검사 통과. 이전용 macOS legacy keychain 호환 API의 deprecated 경고는 남아 있음.

### 후속 표시 변경 및 재로그인 확인

상단바 팝오버의 계정 제목과 도움말을 `Codex(계정 이름 또는 이메일)` 형식으로 변경했습니다. Claude·Gemini도 Provider 이름을 앞에 표시하며 긴 계정명은 줄바꿈합니다. 릴리스 빌드·서명 검사 후 실행 앱과 배포 ZIP에 반영했습니다. 이번 실행에서는 화면 제어의 `Control-F8`이 팝오버를 열지 못해 변경된 팝오버의 직접 시각 검증은 완료하지 못했습니다. 표시 문자열 변경에는 별도 단위 테스트를 추가하지 않았습니다.

같은 후속 확인에서 사용자가 재로그인한 두 Codex 계정의 **자동 갱신** 표시와 실제 잔여율 74%·41%를 Dashboard에서 확인했습니다. 앞서 재로그인이 필요했던 상태는 해소되었습니다. 토큰 만료 후 서버의 실제 갱신까지 관찰한 것은 아닙니다.

### Dashboard의 계정별 상단바 표시 선택

### 상단바만 실행한 상태의 메모리·CPU (2026-10-17)

실제 Codex 2계정의 모니터링·상단바 표시를 켜고 릴리스 앱을 각각 새로 실행했습니다. Dashboard를 열고 닫은 뒤 한 번 재열기/닫기를 수행하고, 마지막 창 닫힘에서 최소 60초가 지난 상태를 90초 동안 2초 간격으로 측정했습니다. 팝오버는 닫혀 있었고 측정 구간에 스캔·quota 요청·창 재열기가 없음을 수명주기 기록으로 확인했습니다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 물리 메모리 점유량 중앙값 | 51.923 MiB | 46.079 MiB |
| 물리 메모리 최소–최대 | 51.923–51.923 MiB | 46.048–46.110 MiB |
| 평균 CPU, 코어 하나 = 100% | 0.0161% | 0.0306% |
| 90초 누적 CPU 시간 | 14.53 ms | 27.55 ms |
| 모니터링 타이머 실행 횟수 | 3회 | 0회 |

물리 메모리는 약 **5.84 MiB / 11.3% 감소**했습니다. **CPU 감소는 이번 측정에서 확인하지 못했습니다.** 양쪽 모두 0.1% 미만이며 변경 후 값이 소폭 높았습니다. 반복 타이머 제거로 앱의 불필요한 확인 작업은 사라졌지만, 이를 CPU·배터리 절감률로 환산하지 않습니다. 이후 5초 스택 샘플에서 메인 스레드의 453개 샘플은 모두 이벤트 대기 상태였고, 작업 스레드에서 macOS Network의 연결 정리 한 샘플이 관측됐습니다. 이 짧은 샘플만으로 전체 CPU 차이의 원인을 확정하지 않습니다.

`proc_pid_rusage`의 `ri_phys_footprint`와 CPU 누적 카운터를 사용했습니다. Apple Silicon의 CPU 카운터는 Mach tick이므로 `mach_timebase_info`의 125/3 배율을 적용했고, 0.25초 CPU 작업을 `time.process_time()`과 비교해 단위를 확인했습니다. 압축·스왑 영향을 받는 RSS는 비교 기준으로 사용하지 않았습니다. 두 실행 모두 수명주기 진단을 켰으므로 변경 전의 타이머 3회에는 진단 파일 쓰기도 포함됩니다. 이 Mac의 단일 비교이며 실제 로그·OS 활동은 변할 수 있습니다.

- 30초 반복 확인을 다음 작업 시각의 일회성 예약으로 변경했습니다. 창을 닫으면 기존 최소 15분 quota 조회를 유지하고 로컬 스캔은 예약하지 않습니다. 잠자기 또는 할 일이 없는 상태에는 타이머를 제거합니다.
- 화면·로그 캐시를 해제한 뒤 2초 후 한 번 메모리 반환을 요청합니다. 이후 반복 실행하지 않으며 창을 빨리 다시 열면 정리를 취소합니다. 스캔 실패 시에는 5분 뒤 다시 시도해 즉시 반복하는 상황을 막습니다.
- 추가 6개 스케줄 검사와 전체 66개 테스트, 릴리스 빌드·서명·패키징된 Claude callback 검사를 통과했습니다. 실제 앱의 창 재열기, 세 탭, 두 계정의 자동 갱신 연결 표시, 수동 새로고침, 표시 스위치 유지와 Dashboard 차트를 확인했습니다. 5분 이상 실행된 앱의 닫힌 창을 열자 기한이 지난 계정·로컬 통계가 자동 갱신되는 것도 확인했습니다. 실계정 토큰을 강제로 만료시키거나 시스템 잠자기를 실행하지는 않았습니다.

- 대기 메모리는 약 **53.1% 감소**했습니다. Dashboard를 열기 전의 초기 값만 사용하지 않았습니다. 최종 배포본에서 Dashboard·계정·설정을 두 차례 순회하고 팝업을 두 차례 연 뒤 모두 닫았습니다. 대기 중 화면 helper는 0개, 상주 프로세스는 1개였고 계정 조회 예약은 유지됐습니다.
- 최종 측정은 60초 안정화 후 90초를 기록했습니다. 끝부분에 팝업이 다시 열린 이벤트가 있어 그 구간을 대기 수치에서 제외하고 **앞의 80.2초**를 사용했습니다. 원본 기록은 그대로 보존했습니다. 별도의 실제 화면 검증 뒤 닫힌 60.1초 구간은 31.157MiB, CPU 0.0021%였습니다. 계정 수·OS 상태·팝업 표시 중에는 수치가 달라질 수 있으며 30MB의 고정 상한을 의미하지 않습니다.
- 추가 팝업 사용과 새로고침 뒤 다시 닫은 상태의 3초 확인은 31.470MiB(약 33.0MB), CPU 0.0020%였습니다. 따라서 사용자 안내에는 관측된 대기 범위 **약 31–33MB, 기존 대비 약 50% 감소**를 사용합니다. 이 짧은 확인은 80초 측정을 대체하지 않습니다. 기록은 `artifacts/memory30-post-refresh-check.json`입니다.
- 상주 화면을 native `NSStatusItem`으로 바꾸고, 팝업 hosting controller는 닫을 때 해제합니다. Dashboard와 로컬 로그 스캔은 창을 열 때만 실행하는 내장 화면 프로세스로 옮겨 창 종료 시 SwiftUI 캐시까지 반환합니다. runtime Dock 아이콘은 같은 원본의 512px PNG를 사용합니다. 활동 히트맵의 기존 UI와 상호작용은 유지했습니다.
- 실제 앱에서 Dashboard·날짜별 모델 상세·두 Codex 계정의 연결 및 자동 갱신 표시·수동 quota 새로고침을 확인했습니다. 다크/시스템 모드, Dock 표시, 세 가지 상단바 형식, 계정별 표시 스위치를 변경하고 복원했습니다. 전체 설정 SHA-256이 변경 전과 같았습니다. 연결 시트에서 존재하지 않는 테스트 파일을 요청해 오류가 전달되고 기존 계정이 유지되는 것도 확인했습니다. 새 실계정 로그인이나 강제 토큰 만료는 수행하지 않았습니다.
- 실제 상단바 **팝업**의 로고·`Codex(계정)` 이름·quota·리셋 시각·내용에 맞는 높이를 확인했습니다. 팝업의 Dashboard/설정 버튼, 창 닫기 후 helper 종료, 다시 열 때 이전 탭 복원도 확인했습니다. 시스템 상단바 전체나 Dock 자체의 새 스크린샷 검증은 이 항목에 포함하지 않습니다.
- 전체 77개 회귀 테스트가 통과했습니다. 신규 5개는 메시지 분할 수신/순서, 길이 상한/잘린 프레임, 1MiB 로그인 데이터 왕복, 다중 계정 표시 상태 전달, 실제 익명 파이프의 전송과 EOF 종료를 검사합니다. 마지막 시작 순서 보완 후 관련 5개 검사와 릴리스 빌드를 다시 통과했습니다. 패키징된 Claude callback, helper 단독 실행 거부, 두 번들의 로고 원본 일치와 번들 내부 리소스 조회, 중첩 앱 서명, ZIP 무결성도 확인했습니다.

## 재현


`--diagnostics /절대/경로.jsonl`을 추가하면 창 표시 여부·스캔 여부·요청 수와 다음 예약 시각을 기록합니다. 이 옵션은 기본적으로 꺼져 있고 계정 이름·이메일·토큰·대화 내용은 기록하지 않습니다. 검사 로그는 `artifacts/tests.log`, `artifacts/build-release.log`, `artifacts/statusline-smoke.log`, 수치는 `artifacts/measurements.json`에 있습니다.

이 환경은 XCTest가 없는 Command Line Tools 설치여서 Swift Testing으로 검사를 실행했습니다. SwiftPM은 native 빌드 엔진을 사용합니다. macOS 27 SDK의 `State` 매크로와 기존 SwiftUI property wrapper가 함께 노출되는 문제를 피하기 위해 wrapper 타입 별칭을 사용합니다. 앱은 웹 런타임·로컬 서버·업데이터를 번들하지 않습니다.

# 자동 업데이트

자동 업데이트는 **0.1.1부터** 지원합니다. 0.1.0에는 이 기능이 없으므로 최신 버전을 한 번 직접 설치해야 합니다. 0.2.2 프리뷰 사용자도 정식 버전으로 한 번 직접 전환해야 합니다. 버전 비교는 숫자로 수행하며 자동으로 낮은 버전을 설치하지 않습니다.

**0.2.1부터 업데이트 서명은 선택 사항입니다.** 공식 GitHub 릴리즈의 HTTPS 주소, 파일 크기와 SHA-256을 확인하고 설치합니다. 0.2.0 이하의 앱에는 서명을 필수로 확인하는 코드가 있으므로, 기존 서명 키가 없다면 0.2.1을 한 번 직접 설치해야 합니다. 이후에는 서명 없는 릴리즈도 자동 업데이트할 수 있습니다.

## macOS 0.1.1·0.1.2 설치 오류

이 버전의 macOS 설치기는 작업 파일을 읽을 때 다운로드 폴더 URL의 끝 슬래시 차이를 다른 경로로 판단해 설치를 거부합니다. 다운로드와 서명 확인은 성공하지만 기존 앱을 유지합니다. **0.1.3 이상을 한 번 직접 설치**해야 수정된 설치기가 적용됩니다. 0.1.3부터 작업 파일에 폴더 URL을 일관되게 기록하며 기존 경로·서명·권한 검증은 유지합니다. Windows 설치기는 영향을 받지 않습니다.

## 사용자 동작

- 설정의 **자동 업데이트**는 기본으로 켜져 있습니다. 앱 시작 15초 후, 이후 실행 중에는 하루에 한 번 GitHub 최신 정식 릴리즈를 확인합니다. 미리보기·초안 릴리즈는 제외합니다.
- 새 버전의 공식 다운로드 주소·크기·SHA-256과 업데이트 목록을 확인한 뒤 디스크에 다운로드합니다. 서명 파일이 있으면 추가로 검증하고, 파일이 없으면 서명 키 없이 진행합니다. 잘못된 서명이나 HTTP 오류를 서명 생략으로 처리하지 않습니다. 다운로드 상태와 오류는 설정에 표시합니다.
- Dashboard가 닫혀 있을 때 설치를 시작합니다. 설정의 **설치 후 다시 시작**으로 즉시 설치할 수도 있습니다. 진행 중인 인증 갱신과 저장을 마친 뒤 종료하며, 새 인증 정보를 저장할 수 없으면 설치를 중단합니다. 계정 정보와 설정은 앱 폴더 밖의 기존 위치에 유지됩니다.
- 자동 업데이트를 끄면 자동 확인·다운로드·설치를 중지합니다. **업데이트 확인**과 수동 설치는 계속 사용할 수 있습니다. 절전 중에는 자동 작업을 중지하고, 미리보기 모드는 네트워크와 설치를 실행하지 않습니다.
- macOS는 같은 볼륨에서 앱을 원자적으로 교체합니다. Windows 설치형은 기존 사용자 설치 위치에서 조용히 설치하며 시스템을 재부팅하지 않습니다. 포터블은 기존 폴더를 교체하고 사용자가 추가한 파일을 보존합니다.
- 새 앱의 시작 확인 전까지 이전 앱을 보관합니다. 새 앱이 실행되지 않으면 복구를 시도합니다. 새 앱이 실행 중이지만 시작 확인을 보내지 않으면 실행 중인 파일을 교체하지 않고 백업을 보존합니다. 실패한 버전은 사용자가 다시 확인하기 전까지 자동 설치를 반복하지 않습니다.

앱이 쓰기 불가능한 폴더에 있거나 설치 파일이 사용 중이면 기존 앱을 유지하고 오류를 표시합니다. 설치 직전에도 파일 크기·SHA-256·버전·설치 경로를 다시 확인합니다. macOS는 인증서가 필요 없는 ad-hoc 서명을 사용하며, 업데이트 서명은 Apple 공증이나 Windows Authenticode 서명과 별개입니다.

## 릴리즈 준비

일반 배포에는 개인 키가 필요하지 않습니다. `scripts/sign-update.py --unsigned`가 검증한 배포 파일로 `update-manifest.json`을 생성합니다. 공식 GitHub API가 제공하는 자산의 크기·SHA-256과 이 목록, 실제 다운로드 바이트가 모두 일치해야 합니다.

1. `shared/version.json`의 버전과 빌드를 올리고 커밋합니다. 두 플랫폼의 Native platforms 작업이 같은 커밋에서 성공해야 합니다.
2. 해당 커밋의 깨끗한 체크아웃에서 두 아티팩트를 내려받습니다. 이전 빌드 파일이 섞이지 않도록 새 폴더를 사용합니다.

   ```sh
   gh run download RUN_ID --name macos-release --dir artifacts/update-input/macos
   gh run download RUN_ID --name windows-x64-release --dir artifacts/update-input/windows
   python3 scripts/sign-update.py \
     --artifacts artifacts/update-input \
     --output artifacts/update-feed \
     --unsigned
   ```

3. 생성 도구는 커밋·버전·빌드·소스 변경 여부와 각 배포 파일의 해시를 검증합니다. 모든 검사가 통과해야 `update-manifest.json`을 생성합니다. `--unsigned`는 환경 변수의 키를 사용하지 않으며 출력 폴더의 이전 `update-manifest.sig`를 제거합니다.
4. 릴리즈를 게시할 때 플랫폼 파일 세 개와 **업데이트 목록**을 같은 `vVERSION` 릴리즈에 첨부합니다. 검증 이후 ZIP·EXE를 다시 압축하거나 바꾸면 안 됩니다. 체크섬을 포함한 모든 파일을 초안에 올린 뒤 최신 정식 릴리즈로 공개합니다.

필수 파일 이름은 `QuotaBar-VERSION-macOS-arm64.zip`, `QuotaBar-VERSION-Windows-x64.zip`, `QuotaBar-VERSION-Windows-x64-Setup.exe`, `update-manifest.json`입니다. GitHub 자산의 `sha256:` digest, 목록의 해시, 실제 다운로드 바이트가 모두 일치해야 합니다.

이전 클라이언트를 위해 서명도 제공하려면 `--unsigned` 대신 `--private-key .tools/update-signing/private.pem`을 지정합니다. 앱에는 기존 P-256 공개 키만 포함하며 개인 키는 로컬에 보관합니다. **개인 키를 GitHub 시크릿, CI 또는 릴리즈 첨부 파일에 전송하지 않습니다.** 서명 파일을 첨부할 경우 앱의 기존 공개 키와 일치해야 합니다.

## 검증

Rust 검사는 서명 없는 다운로드·설치 전 재검사, 손상된 파일 거부, 취소 후 임시 파일 정리와 선택적 서명을 확인합니다. `python3 -m unittest discover -s scripts/tests -v`는 개인 키 없는 목록 생성과 기존 서명 방식을 모두 검사합니다. CI에는 생산용 개인 키를 제공하지 않습니다.

별도 Windows CI 작업은 레거시에 보관한 검증 스크립트로 두 버전의 앱을 만듭니다. 직접 설치 도우미 검사에는 기존 서명·변조 거부 사례를 유지하고, 세 가지 상주 앱 시나리오는 서명 파일 없이 자동 다운로드·포터블/설치형 업그레이드·시작 확인·롤백·설정 보존을 검사합니다. 테스트 앱과 키는 배포 아티팩트로 업로드하지 않습니다.

자동 업데이트 상태는 macOS의 `~/Library/Application Support/AIUsage Lite/Updates`, Windows의 `%LOCALAPPDATA%\QuotaBar\Updates`에 기록됩니다. 실패 시 이곳의 `last-result.json`과 대상 앱 폴더 옆의 백업을 확인할 수 있습니다. 자동으로 복구하지 못한 백업은 앱을 종료한 뒤 수동 복구할 수 있도록 남깁니다.
